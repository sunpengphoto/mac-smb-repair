# mac-smb-repair

用于 macOS 上一类 SMB 连接卡住问题的保守检测与局部修复工具。

它针对的现象是：服务器重启、网络切换或旧连接异常中断后，Finder 一直显示“正在连接”，而 macOS 的 `NetAuthSysAgent` 可能保留了无法完成的 SMB 挂载请求。

脚本不保证解决全部 SMB 问题。网络不可达、服务器端 SMB 服务未启动、账户权限或凭据错误、名称解析失败等情况，需要分别排查。

## 使用场景

- Finder 的 SMB 连接长时间停在“正在连接”。
- 重新连接没有立即出现登录窗口。
- 已确认问题更可能在 Mac 端的网络登录组件，而不是想直接重启整台 Mac。

脚本不会检查或访问任何服务器；运行前请自行确认服务器与网络状态。

## 一键修复脚本

下载项目后，在 Finder 中双击 [NetAuthSMBRepair.command](./NetAuthSMBRepair.command)。它会打开终端并显示检测结果。

推荐通过 GitHub 项目的 **Code → Download ZIP** 下载完整项目，解压后双击该文件。若 macOS 拦截首次运行，请在 Finder 中按住 Control 点击文件，选择“打开”。

下载脚本后如没有可执行权限，在终端运行：

```sh
chmod +x NetAuthSMBRepair.command
```

只想检查、不修复时：

```sh
./NetAuthSMBRepair.command --check
```

## 命令

脚本在确认故障特征后，等效于对该进程发送正常终止信号：

```sh
kill -TERM <NetAuthSysAgent 的进程号>
```

不建议在未检测的情况下直接使用宽泛的按名称结束进程命令。此脚本会先确认进程属于当前用户、在两次采样之间没有被替换，并且只结束那个已确认的进程。

## 检测与修复逻辑

脚本连续进行两次 3 秒采样，中间间隔 2 秒。只有两次都同时满足以下条件才会修复：

1. `NetAuthSysAgent` 主线程的大部分样本持续等待内部锁。
2. 一个 SMB 挂载路径同时持续等待账户 SID 的 RPC 查询。

满足条件后，脚本向该进程发送 `TERM`。macOS 会在需要时重新启动它；Finder 和其他应用不会被脚本重启。

没有检测到特征时，脚本会报告“未发现”并不做任何修改。采样工具不可用、进程在检测期间改变、或者采样格式无法可靠解析时，脚本会报告“无法判断”并不做任何修改。

## 问题背景与原因简述

Finder 通过 macOS 的网络登录组件建立 SMB 连接。服务器重启或连接中断后，旧请求有时不能正确结束，新的 Finder 请求就可能一直等待这个组件返回。

本项目处理的是其中一种可观察到的阻塞调用链：主线程卡在内部锁等待，同时 SMB 挂载线程停在账户 SID 的 RPC 查询。结束该组件可清除这些悬挂请求，避免为了恢复这类问题而重启整台 Mac。

这是一种有针对性的恢复措施，不是对 macOS 或 SMB 服务器故障的通用诊断结论。

## 隐私与安全

- 仓库和脚本没有服务器地址、设备名、用户名、密码或挂载路径。
- 脚本不访问网络，不读取钥匙串或文件内容，也不自动连接服务器。
- 采样仅在系统临时目录中短暂保存；脚本退出时清理，不上传、不显示原始内容。
- 修复操作只会结束已确认、且属于当前用户的 `NetAuthSysAgent` 进程。

## 兼容性

面向包含 `/usr/bin/sample` 的 macOS 系统，并使用系统自带的 `zsh`、`awk`、`ps`、`pgrep`、`mktemp` 和 `kill`。如果某个系统缺少所需工具，脚本会停止并报告“无法判断”，不会尝试修复。
